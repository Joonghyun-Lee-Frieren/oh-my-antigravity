# OmA 컨텍스트 엔지니어링

의도는 짧은 문맥으로 전달하고, 제약은 도구와 상태 전이로 적용합니다.

- SKILL.md는 20줄 이내 진입점으로 유지하고 자세한 절차는 references에 둡니다.
- 읽기 전용 oma-doc-reader가 문서를 먼저 읽고 출처·제약·불확실성을 요약합니다.
- 설계 턴에서 파일 범위·검증 조건·실행할 검사 명령을 확정하고 턴을 종료합니다.
- 다음 사용자 턴부터 메인 대화가 코드를 수정합니다. 서브에이전트는 제안만 반환합니다.
- 실제 검사 결과와 코드 해시를 기록하고, 리뷰어에게 최대 120줄짜리 섹션 하나씩 전달합니다.
- Stop은 통과한 파일을 잠그고 한 실행에 최대 3개 수정 단위를 배정합니다.
- 증거·서비스·권한이 없으면 실패나 unknown을 정직하게 남깁니다.

상시 문맥에 모든 운영 모드나 전체 스키마를 넣지 않습니다. 필요한 단계의 참조만 읽고,
문서 전체 대신 요약을 인계합니다. 상태와 로그는 컨트롤러가 관리합니다.

이 구조는 도구 수준의 제약이며 코드 의미상 정직성을 자동으로 증명하지는 않습니다.
관련 동작 검증과 작은 리뷰를 함께 사용해야 합니다. 모델은 CLI에서 선택하고 작업자는 상속합니다.

## 의도와 세션 연속성

Scope Brief는 결정권과 문서 충돌을 기록하고, Design Check는 정확한 계획을 독립 검토합니다. 리뷰어의 실제 대화에서 보낸 결과만 훅이 수집하므로 부모가 PASS를 대신 작성할 수 없습니다. Evidence Window는 로그 읽기를 제한하고, Session Trail은 체크포인트와 현재 소스를 비교합니다. 예전 소유권이나 승인을 복원하지 않습니다.
